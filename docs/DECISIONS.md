# Decision log

| Date | Decision | Context | Alternatives considered |
|---|---|---|---|
| 2026-09-22 | Android-only v1 | iOS background BLE advertising is restricted; 90%+ of target users on Android | Cross-platform (Flutter/RN) — rejected, BLE plugins immature for advertising |
| 2026-09-22 | Advertising-only mesh, no GATT | Connections fail at radio density | Bridgefy-style connections; Wi-Fi Aware (Android-only, patchy OEM support) |
| 2026-09-22 | 24-byte fixed packet, codebook not chat | Must fit legacy advert; survives congestion | Extended advertising (BLE 5 gating); fragmentation (fragile) |
| 2026-09-22 | Geo-routed relay with flood fallback | Reduce rebroadcast volume | Pure flooding (Bridgefy) — storms at scale |
| 2026-09-22 | No encryption in v0 | Speed to first field data | Encrypt from day one — adds a week; deferred to v1.1 with content-only encryption |
| 2026-09-22 | Static map image + JSON calibration | Offline, simple | Tile-based offline maps — heavier, unnecessary for one venue |
| 2026-09-22 | No DI framework | Small app, one container | Hilt — fine later if the app grows |
| 2026-09-22 | Kotlin package `com.firefly.app`; Play application ID stays `in.firefly.app` | `in` is a hard Kotlin keyword, so `package in.firefly.app` needs backticks in every file and import. The applicationId is what users and the Play Store see and is unaffected. | Backticked `in.firefly.app` packages everywhere — rejected, constant friction and IDE noise |
| 2026-09-22 | Toolchain: AGP 9.4.1 with built-in Kotlin (no `kotlin-android` plugin), Kotlin 2.4.20, KSP 2.3.12, Gradle 9.7.1, JDK 21, compileSdk 37.2 / targetSdk 37 / minSdk 26 | Latest stable everything per CLAUDE.md. Android 16+ ships minor SDK versions, so `compileSdkMinor = 2` is set alongside `compileSdk = 37`. | Pin to AGP 8.x — rejected, would be a forced migration within months |
| 2026-09-23 | Scan duty cycle defaults to 8 s on / 4 s off (not 4/2) | Same 66 % duty as PROTOCOL.md §6, but a 12 s period keeps us at 2.5 scan starts per 30 s, well under Android's silent 5-per-30 s throttle. Configurable for field builds. | 4/2 (6 s period) — exactly at the throttle limit, silent failure mode |
| 2026-09-23 | `seq` starts at a random value each service start | A restart within the 5-minute dedupe TTL would otherwise reuse low seq numbers and be dropped by peers. Persisting the counter was judged not worth the writes. | Persist last seq in DataStore |
| 2026-09-23 | Beacon is sent with lat/lon = 0 and accuracy bucket UNKNOWN before the first GPS fix | Announces presence immediately so a friend sees you in the member list; receivers treat (0,0) as "no position". | Wait for a fix before advertising |
| 2026-09-23 | Foreground service type `connectedDevice|location`; service only starts after all runtime permissions are granted | Android 14+ throws if the location type is used without location permission. | Start early and degrade |
| 2026-09-23 | Venue-agnostic by default: free north-up grid map with auto-zoom; venue packs are optional zips loaded by the user, never bundled | Product must work at any large crowd, not one event. Bundling a venue would tie releases to venues. | Bundled pack per event (rejected); tile-based offline maps (heavy, needs per-city data) |
| 2026-09-23 | Pings burst for 600 ms per repeat at the normal 250 ms advertising interval; ACKs are sent ×2 with 150–700 ms jitter | Changing the advertising interval per burst needs disable/re-enable of the advertising set, which is flaky across chipsets. 3 × 600 ms bursts ≈ 7 adverts per ping. ACK repeat count is unspecified in PROTOCOL.md; 2 balances reliability and air time. Field builds can tune both. | Low-latency interval during bursts (revisit in Phase 5 if delivery < 70 %) |
| 2026-09-23 | QR payload is `firefly://join/CODE`; the scanner also accepts a bare 6-character code | Leaves room for OS deep-linking later; still readable by any QR app. | Bare code only |
| 2026-09-23 | QR scanning uses CameraX + the *bundled* ML Kit barcode model (offline); generation uses ZXing core | The Play-services ML Kit variant downloads its model over the network, which Firefly cannot rely on. Cost: debug APK grows from 15 MB to 39 MB (release shrinks with R8). | ZXing for decoding too (slower, more code); no QR |
| 2026-09-23 | Without a venue pack, POI-kind messages send arg 0 = "here" and carry the sender's position | Keeps Meet at / Going to usable anywhere. | Disable those messages without a pack |
| 2026-09-23 | Scan 8 s on / 2 s off (was 8/4) and PING repeats 1.5 s apart (was 1 s) | Field test: some replies never arrived. A 3×1 s ping spans 2.6 s and could fall entirely inside a 4 s scan-off gap (~12 % loss). Now a ping spans 3.6 s > 2 s gap, so at least one burst always meets an open scanner. Costs ~14 % more scan time; measured in Phase 5. | Keep 8/4 and send ×5; cut bursts to 100 ms interval |
| 2026-09-23 | Geo-routing gate compares my distance to the target against the *originator's* position carried in the packet (not the last relayer's) | The 24-byte packet only carries the originator's lat/lon. Comparing against the previous hop would need per-hop state we do not have. Effect: the gate is slightly permissive on multi-hop paths, never restrictive. | Add a relayer position field (no room in 24 bytes) |
| 2026-09-23 | Relay queue drops entries older than 5 s unsent; capacity 32; equal-priority arrivals are refused when full | A beacon relayed 5 s late is worse than none (stale dot); refusing equals keeps the eldest, so the queue cannot be thrashed by a burst. | Unbounded queue; newest-wins |
| 2026-09-23 | SOS is long-press only, repeats every 60 s until cancelled from a persistent red bar; receivers keep the SOS banner until dismissed | PRD F1 + PROTOCOL.md §4. Accidental SOS in a crowd would flood the mesh with TTL 15 packets. | Confirm dialog (slower under stress) |
